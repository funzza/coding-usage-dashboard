# Quota 采集调研需求书

> 给调研 agent 的任务说明。目标:为 Coding Usage Dashboard 的"订阅额度"功能做可行性调研。
> **只做调研,不写集成代码。** 每家订阅产出一份独立报告。

## 背景

我们正在开发一个 Windows 本地桌面应用(Electron),用 ccusage 展示各 Coding Agent 的 token 用量。
下一步要加入**订阅额度(Quota)展示**:每个订阅当前周期用了多少、剩多少、什么时候重置。

当前订阅清单(都需要调研):

1. **Kimi**(Moonshot,月之暗面 — kimi.com / Kimi Code CLI)
2. **Grok**(xAI)
3. **GPT**(OpenAI,ChatGPT/Codex 订阅)
4. **OpenCode Go**(opencode 的订阅计划)
5. **阿里 Token Plus**(阿里云百炼的 Coding Plan / Token Plan,模型名形如 `alibaba-token-plan-cn/...`)

## 调研环境

- 上述订阅都在本机真实使用中,对应的 CLI / 桌面客户端已安装并登录过

## 每家订阅需要回答的问题

### 1. 额度体系(先搞清楚,再找数据)

- 额度周期是什么?(滚动 5 小时 / 自然周 / 自然月 / 固定窗口)
- 额度单位是什么?(token 数 / 请求数 /  Credits / 金额)
- 重置规则是什么?用户能不能看到"当前周期已用/总量/剩余/重置时间"?

### 2. 采集方式 A:本地数据(优先级最高)

检查本机是否存在可读的额度信息:

- 配置/缓存目录里的文件(典型位置:`C:\Users\funzza\.<产品名>\`、`%APPDATA%`、`%LOCALAPPDATA%`)
- CLI 是否内置查询命令(例如 `xxx quota`、`xxx status`、`xxx usage` — 以 `--help` 实测为准)
- 本地日志里是否周期性地记录 quota 响应

对发现的每个数据源,记录:**完整路径、文件格式、真实内容示例(脱敏)、更新时机、字段含义**。

### 3. 采集方式 B:官方 API

如果本地没有,或本地数据不完整,找官方接口:

- 控制台/网页版里"用量/额度"页面背后调用的接口(用 DevTools Network 抓)
- 官方文档里的 billing / usage / quota API
- 认证方式:token 存在本机哪里?能否复用 CLI 已登录的凭据?还是要单独申请 API key?

对确认的接口,记录:**完整 URL、方法、请求头(脱敏)、真实响应 JSON(脱敏)、字段含义、调用频率限制**。

### 4. 结论

- 可行性评级:**本地可读 / 官方 API 可用 / 只能抓网页(脆弱)/ 不可行**
- 推荐的采集方式和理由
- 风险:接口是否公开、是否可能变动、ToS 是否允许程序化访问

## 红线(必须遵守)

- **凭据安全**:报告中所有 token / cookie / key 必须脱敏(保留前 4 位 + `...` 即可)。不要把任何凭据上传到任何地方。
- **只读**:不要修改任何本地配置文件,不要登出/重新登录,不要触发会改变账户状态的操作(如取消订阅、升级)。
- **不装新订阅/不付费**:只调研已有的五个订阅。
- **实测为准**:所有结论必须有真实证据(文件截图路径、真实响应 JSON),不允许"根据文档应该有"。文档和实测冲突时以实测为准并注明。
